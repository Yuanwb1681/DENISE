# DENISE MPI+CUDA work tree

This is an isolated MPI+CUDA derivative of DENISE Black Edition. The original
tree at `/home/ywb/DENISE-Black-Edition` is not modified.

## Build and launch

```bash
make -C libcseife
make -C src -j4 denise
mpirun -np 1 ./bin/denise_gpu parameter.inp workflow.inp
```

The unified executable `bin/denise_gpu` supports AC, P-SV, SH, VTI and TTI.
Each MPI local rank binds to `local_rank % visible_cuda_devices`. The default
build target is `sm_75` (the local GTX 1650); override it with
`make CUDA_ARCH=sm_XX` when required.

## CUDA coverage

- AC: pressure, velocity, explosive source, free surface and receiver sampling.
- P-SV: elastic/viscoelastic stress, velocity, explosive and force sources,
  free surface and receiver sampling.  The elastic single-GPU path submits
  propagation, sampling and FWI kernels asynchronously on the default stream.
- SH: elastic/viscoelastic stress and velocity.
- VTI/TTI: anisotropic stress kernels, including distinct TTI staggered
  `d15/d15h` and `d35/d35h` coefficients; velocity uses the P-SV CUDA kernel.
- FWI/RTM: forward-wavefield storage and adjoint correlations for AC, P-SV,
  SH, VTI and TTI. Propagation kernels are shared by forward and adjoint modes.
- Float vectors, matrices and three-dimensional relaxation tensors use CUDA
  managed memory so existing MPI boundary exchange remains valid.

CPU MPI still performs boundary packing/MPI calls for multi-rank runs, model
I/O, optimization and filtering.  For a single P-SV rank, redundant halo
exchange is skipped and synchronization occurs only before an actual CPU read
(snapshot/preconditioner), a multi-rank exchange, or the end of propagation.
Other physics paths retain their conservative wrapper-level synchronization.
CUDA-aware MPI and explicit device allocations remain future multi-GPU work.

The P-SV energy accumulator used by `EPRECOND=1/3` now runs on the GPU, so
`DTINV` sampling no longer forces a host synchronization. Managed allocations
are registered and prefetched to the selected GPU before each single-rank P-SV
propagation. Residual/filter/model-update stages remain on the CPU because they
run once per shot or iteration and immediately feed MPI reductions or file I/O.

CUDA paths can be isolated with the `DENISE_GPU_DISABLE_*` environment switches
defined at their call sites, including `AC`, `PSV`, `SH`, `VTI`, `TTI`, visco
stress and FWI/RTM correlation switches.

A four-stage, one-iteration-per-stage `MODE=1` P-SV FWI smoke run completed
forward modelling, residual construction, adjoint propagation, CUDA gradient
correlation, GPU energy preconditioning, step-length control and model output
in 8.92 seconds versus
17.39 seconds for one CPU/MPI rank.  A 2x2, four-rank CPU/MPI run took 3.62
seconds, so it remains 2.46 times faster than the single GTX 1650 for this small
case. Final Vp, Vs and density files from the one-rank comparison were bitwise
identical. Its observed data were generated by the same starting model, so the
near-zero misfit intentionally produced no non-zero optimum step.

A corresponding one-iteration SH FWI run completed the same path and wrote Vs
and density models in 39.42 seconds. It likewise reported a zero optimum step
because the observed data and starting model were intentionally identical.

Regression inputs and CPU references are under `tests/`. Short cases may be
slower on GPU because launch synchronization and managed-memory migration
dominate their arithmetic workload.
